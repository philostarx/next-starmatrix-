## 1. API 설계 개념

- API (Application Programming Interface)는 
  → 클라이언트(프론트엔드)와 서버(백엔드) 간 데이터를 주고받는 인터페이스이다.

- API 서버의 핵심 역할:
  1. 요청 수신 (Request)
  2. 데이터 추출 및 처리 (Processing)
  3. 응답 반환 (Response)

- 이 흐름은 클라이언트와 서버 간의 데이터 흐름을 실현하는 구조이다.

---

## 2. 데이터 흐름 구조 (요청-처리-응답)

| 단계 | 역할   | 예시                      |
|------|--------|---------------------------|
| 클라이언트 → 서버 | 요청   | GET /api/users/1         |
| 서버 내부          | 처리   | DB 조회, 계산, 필터링 등 |
| 서버 → 클라이언트 | 응답   | { "id": 1, "name": "홍길동" } |

- 이 흐름은 실시간 처리 또는 배치 처리로 구분 가능하다.

---

## 3. HTTP 요청 메서드와 CRUD 매핑

| HTTP 메서드 | 의미   | RDB 개념(CRUD) |
|-------------|--------|----------------|
| GET         | 조회   | Read (SELECT)  |
| POST        | 생성   | Create (INSERT)|
| PUT/PATCH   | 수정   | Update         |
| DELETE      | 삭제   | Delete         |

- 이 메서드들은 자원에 대한 행위(동작)를 명시한다.

---

## 4. RESTful API 설계 방식

> RESTful = 자원(URI) + 행위(HTTP Method)

| 구성 요소   | 설명                           | 예시                     |
|-------------|----------------------------------|--------------------------|
| 자원 (URI)  | 무엇을 대상으로 하는가?         | /users, /products/1      |
| 행위 (Method) | 그 자원에 대해 무엇을 할 것인가? | GET, POST, PUT, DELETE   |

- RESTful은 표준화, 예측 가능성, 유지보수 용이성을 강조한다.

---

## 5. 요약 문장

> API 설계의 본질은  
> - 클라이언트와 서버 간 데이터 흐름을 명확히 구성하고,  
> - RESTful 방식으로 자원(URI)과 행위(Method)를 명확히 구분하여 설계하는 것이다.
